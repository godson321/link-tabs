# 选区完整链接拖动直开 — 设计说明

| 项目 | 信息 |
|---|---|
| 状态 | 待用户审阅 |

| 范围 | `src/content/link-interceptor.js` 的选区拖动识别 |

## 目标

用户拖动选中文本到页面空白处时：

- 选区完整覆盖一个可拦截的 `<a>` 链接时，直接打开该链接的真实 `href`。
- 选中文字本身是完整的绝对 `http://` 或 `https://` URL 时，直接打开这段文字。
- 其他选中文字继续按当前搜索引擎搜索。

两种直开情况都沿用现有链接拖动的规则匹配和后台/前台打开设置。

## 现状与问题

`src/content/link-interceptor.js` 的 `dragstart` 先计算选区搜索条件。只要选区可搜索，就把拖动目标记录为 `{ kind: "search", text }` 并提前返回，导致选中的链接文字无法进入现有链接拖动分支。

现有 `resolveLinkTarget(anchor)` 已统一处理可拦截链接的限制：下载链接、编辑区域、非 HTTP(S) 协议和同文档片段保持浏览器原生行为。直开识别应复用这个函数。

## 设计

### 1. 拖动目标识别顺序

在 `dragstart` 中保留当前的可信事件、修饰键、输入区域和选区归属检查，并在搜索分支前加入直开判断：

1. 找到拖动源所属的最近 `<a href>`。
2. 用单个 `Range` 的边界比较判断选区是否完整覆盖该 `<a>` 的内容；该判断支持链接内部存在嵌套元素。
3. 如果完整覆盖链接，调用 `resolveLinkTarget(anchor)`。解析成功则记录 `{ kind: "link", href: target.href }` 并结束本次识别。
4. 如果当前选区没有完整覆盖 `<a>`，再把选区文字去除首尾空白，使用 `new URL(text)` 解析，并只接受 `http:` 和 `https:` 协议。解析成功则记录 `{ kind: "link", href: target.href }` 并结束本次识别。
5. 其余满足现有搜索条件的选区记录为 `{ kind: "search", text: selectionText }`。
6. 不满足现有拖动条件的情况保持原生行为。

完整 `<a>` 选择使用链接真实 `href`；纯 URL 选区使用 URL 解析后的标准化地址。URL 文本不接受相对地址、脚本协议、邮件协议或带额外普通文本的内容。

### 2. 后续打开流程

直开目标统一使用已有的 `kind: "link"` 分支：

- `resolveActionDiagnosed(target.href, "drag")` 继续按链接拖动规则匹配。
- `requestOpenLinkTab` 接收相同的后台或前台动作。
- 页面放置区、输入框、可编辑区域、窗口失焦、内嵌框架和视口外松手等现有拖动边界不变。

文字搜索仍使用 `kind: "search"`，按当前页面地址匹配搜索规则并调用 `buildSearchUrl`。

### 3. 代码边界

DOM 选区、`Range` 和 `<a>` 覆盖关系保留在内容脚本中，因为 `src/shared/drag.js` 当前是无 DOM 依赖的共享纯逻辑模块。绝对 URL 解析也在内容脚本中完成，以便直接复用当前页面 URL、链接过滤和错误处理上下文，不改变共享规则模块的职责。

## 失败处理与兼容性

- 选区不存在、包含多个 Range、无法创建 Range 或 URL 解析失败时，继续尝试现有搜索路径。
- URL 解析只允许 HTTP(S)，避免把 `javascript:`、`mailto:` 等协议交给打开标签页的消息接口。
- 完整 `<a>` 的目标若未通过 `resolveLinkTarget`，不改用选区文字绕过现有链接过滤规则，继续按普通选区处理。
- 当前设置未加载、扩展上下文失效或规则计算结果为原生行为时，沿用现有的保守处理。

## 验证场景

需要验证以下行为：

1. 完整选中普通 `<a>` 的文字时打开其 `href`。
2. 完整选中带嵌套元素的 `<a>` 文字时仍打开其 `href`。
3. 只选中 `<a>` 的部分文字时继续搜索。
4. 选中页面中的完整 `https://...` 或 `http://...` 文字时直接打开该 URL。
5. URL 前后有空白时可识别，URL 中混入普通文本时继续搜索。
6. 下载链接、非 HTTP(S) 链接、同文档片段和带修饰键的拖动保持现有行为。
7. 页面放置区、输入框、可编辑区域和拖拽取消流程保持现有行为。

验证使用现有 Node 测试命令和 Edge 解压扩展的真实拖动场景；实现阶段只增加完成该需求所需的最小代码与文档同步。

## 方案比较

- **推荐并选用：内容脚本内增加选区直开识别。** 只调整当前搜索优先级，复用现有链接目标过滤和打开流程，改动面最小。
- **提取共享选区分类器：** 可以增加纯函数测试入口，但 DOM 选区对象仍需由内容脚本组装，会扩大共享模块接口，当前需求收益有限。
- **仅按选中文字解析 URL：** 能覆盖纯 URL 文本，却无法满足完整选中链接标签文字时打开其真实 `href`。
